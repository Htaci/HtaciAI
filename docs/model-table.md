# 内置模型表

记录需要添加的模型图标/服务商图标，Claude code生成。

| 文件 | 角色 |
|---|---|
| `HtaciAI/Services/ModelTable/models.ini` | **权威来源**。要改配置就改它。 |
| `tools/ModelTableGen/` | 生成器。把 ini 编译成 C# 常量。 |
| `HtaciAI/Services/ModelTable/BuiltinModelTable.g.cs` | 生成物，**不要手改**。 |
| `HtaciAI/Services/ModelTable/ModelTableIndex.cs` | 运行时索引：规范化 + 两级匹配。 |
| `HtaciAI/Services/ModelTable/VendorIcons.cs` | 开发商 → 头像资源路径。 |

改完 ini 后：

```bash
dotnet run --project tools/ModelTableGen
dotnet build HtaciAI/HtaciAI.csproj
```

生成器**不是**构建的一部分，只有你会跑它。生成失败时会以非零码退出并逐条列出问题，
不会写出半成品文件。

## 为什么是「编译进程序的表」而不是运行时读文件

- 启动零解析开销，也没有「配置文件丢失 / 被改坏」这种失败路径；
- 模型上新要发版，本来也不需要热更新；
- 但作者体验仍然是改文本，不用碰 C#。

## 两级匹配

添加模型（「获取模型」批量添加、或手工添加）时，拿**模型调用 id** 去查表：

```
1. 命中 [model:...]     → 配置完整，界面上没有提示
2. 只命中 [vendor:...]  → 只知道是谁家的（头像对得上），挂黄叹号
3. 都没命中             → 挂灰问号，全部取保守默认
```

命中结果记在 `ai_model.config_origin` 里，**只有「表里没认全」的行才会出现提示图标**。
点一下图标直接进该模型的编辑页，补完保存即消失（保存会把来源改成 `Manual`）。

这一点是整套机制能否自我维持的关键：**一个点不开、补不掉的提示，用户看几次就学会无视了。**

来源的四个取值（`Models/ModelConfigOrigin.cs`，**只增不改**——它以整数落在库里）：

| 值 | 含义 | 界面 |
|---|---|---|
| `Unmatched` | 表和开发商反推都没命中 | 灰问号 |
| `VendorOnly` | 只反推出开发商 | 黄叹号 |
| `Builtin` | 精确命中内置表 | 无提示 |
| `Manual` | 用户自己填的或改过的 | 无提示 |

升级到本版本之前已有的模型行，迁移时会一律标成 `Manual`：它们本来就是用户手工配置的，
不该因为内置表上线就突然挂上「配置需要补充」。

## 不猜：未知一律退到安全侧

匹配不到时**绝不填猜测值**，而是取最保守的默认：

| 字段 | 未知时 | 为什么 |
|---|---|---|
| `array_content` | 按不支持处理（发纯文本 content） | 猜「支持」会让不支持的服务端拒绝整个请求 |
| `thinking` | 关闭，不下发任何思考字段 | 下发模型不认识的字段会 400 |
| 思考档位 | 只给 `NoThink` 与 `none` | 这两个是仅有的「不会因为猜错档位名而失败」的选项 |
| `temperature` | null = 不下发 | 不传永远安全 |

代价是多模态模型没进表时图片会静默降级成文本——不好受但不崩，而且这正是黄叹号存在的理由。

**未知与「不支持」是两种不同的东西**，数据库里用 `NULL` / 三态区分，不要合并：
合并之后就再也分不出「服务端明确拒绝」和「我们没查过」了。

## 规范化：只做无歧义的机械变换

查表前把 id 折叠一遍（两边都折叠）：转小写、去掉命名空间前缀（`openai/gpt-4o` → `gpt-4o`）、
下划线转连字符、剥掉售卖形式的变体后缀（`:free` / `:nitro` / `(beta)`）、
剥掉日期快照（`-2024-08-06` / `-250905`）。

刻意**不做**判断类变换：「`-thinking` 到底算不算同一个模型」没有确定答案，
而且**多归一化一步就可能把两个不同型号折叠成一个，那比匹配不上更糟**。
这类情况需要时显式写进 `aliases`。

## 关于 `temperature` 和 `max_out`

这两个字段**目前只驱动界面，不下发请求**：应用里还没有往请求体写 `temperature` /
`max_tokens` 的地方。表格如实记录它们，是为了(a)现在就能把没意义的旋钮置灰、
(b)将来加下发逻辑时数据已经在了。

`temperature` 记准尤其重要：部分模型在思考模式下会**收下这个参数却不生效**
（DeepSeek 文档原文：「不会触发错误，但也不会有任何效果」）。
静默失效比报错难查得多——界面照常，效果为零，用户永远发现不了。

## 价格不进表

价格按区域与时段浮动（DeepSeek 就分峰谷价），写死在这里必然误导。
价格在各模型自己的配置里填。

## 数据怎么来的

每条模型都带 `source`（官方文档 URL）和 `note`（数字的含糊之处）。
**填数字前先查官方文档，查不到就写 `unknown`。**

文档只写约数时（`1M` / `128K` / `64k`）按十进制读（`1000000` / `128000` / `64000`），
并把文档原文写进 `note`。这是一条**明写在案的约定**，不是逐条猜测——有约定才能复核。

## 已知缺口

这几条都属于 provider 协议层，模型表本身已经如实记录了模型那一侧的事实：

1. **「关闭思考 / `effort=none`」表达不出来。** OpenAI 的 `gpt-6-sol`、DeepSeek 的
   `deepseek-flash` 都支持用它关掉思考，而 `ThinkingMode` 只有
   `NoThink`（写 `thinking` 开关对象）和 `Default`（什么都不写）。
   对 `ThinkingField` 设成 `ReasoningEffort` 的端点，`NoThink` 目前等同于 `Default`。
2. **Gemini 的 `thinking_level` 在 provider 层没有对应写法**，
   档位记了也发不出去（`ThinkingFieldKind` 只有 `think` / `enable_thinking` /
   `reasoning_effort` / `none`）。
3. **`temperature` / `max_tokens` 还没有下发处**，见上文。

## 头像

开发商图标在 `HtaciAI/Assets/icon/models/{light,dark}/<开发商>.svg`。

- 开发商表里的 `icon` 可以覆盖文件名，因为图标是按**品牌**画的：
  智谱的图标叫 `glm.svg`、xAI 的叫 `grok.svg`。
- 暗色图标目前只是浅色的子集（应用钉死在浅色主题，见 `App.axaml`）。
  解析时「暗色缺失就退回浅色」，等真做深色适配时不会出现一半模型变空白。


四个目录（`models/{light,dark}`、`providers/{light,dark}`）都保留着，内含 `.gitkeep`
以免被 git 当成空目录丢掉。放入新图标后**必须重跑生成器** —— 可用文件名是扫描目录
固化进 `BuiltinModelTable.g.cs` 的，不重跑生成器的话图标放了也不生效。

放回图标后头像仍不会显示：项目**没有 SVG 渲染器**（依赖里没有 `Avalonia.Svg.Skia`）。
需要引入该依赖，再把 `VendorIcons.Resolve(…)` 返回的路径加载成图片。
在那之前界面显示的是开发商名称文本。

## 新增一家厂商 / 一个模型

1. 在 `models.ini` 加 `[vendor:xxx]`（含锚定开头的 `match` 正则）或 `[model:xxx]`；
2. 跑生成器；它会检查未知键名、引用不存在的开发商、重复定义、非法正则，并提示缺图标；
3. 编译。

生成器对**未知键名**是报错而不是忽略：一个写错的键名如果被静默丢弃，
表现是「某个字段莫名其妙没生效」，那种问题在几百行的表里极难排查。
